# SSI Digital Yard 대시보드

프로젝트 루트에서 실행합니다. 별도 패키지나 지도 API 키가 필요하지 않습니다.

```sh
python3 dashboard/serve.py
```

브라우저에서 http://127.0.0.1:8080 을 엽니다. 시작할 때 원본 결과와 CSV에서 데이터를 자동으로 생성합니다. 결과가 변경되면 서버를 재시작하고 새로고침하세요. 포트가 사용 중이면 `python3 dashboard/serve.py --port 8081`로 실행합니다. 데이터만 갱신하려면 `python3 dashboard/build_data.py`를 실행하세요. `index.html`을 파일로 직접 열면 데이터 요청이 차단될 수 있습니다.

- 날짜 선택, 일별 슬라이더, 이전/다음 날짜, 0.5–4배속 재생
- GPS 기반 미터 좌표를 겹침 없이 보정한 지도에서 휠·핀치 확대, 드래그 이동, 더블클릭 확대, 전체 보기
- 구역별 이동, 블록 배치 / 점유율 전환, 미니맵, 마우스 오버 상세, 지도 크게 보기
- 날짜별 이동량 그래프 클릭, 일별 슬라이더, 같은 날짜 이동 다시 재생
- 키보드: 지도 포커스 후 방향키로 이동, `+`/`-` 확대·축소, `0` 전체 보기, `Esc` 큰 지도 닫기
- 실제 면적 비율의 적치장 및 길이×폭 비율의 블럭 도형
- 당일 입고·출고·직행 경로 애니메이션과 이동 목록 / 적치장 / 보관 블록 검색
- 적치장별 점유면적·점유율, 개별 블럭의 치수·입출고일 조회

## 데이터와 해석

`runs/milp/result.json`의 배정과 일별 이동을 사용하며, `raw-data/block_schedule.csv`에서 블럭 치수를, `raw-data/적치장 노드 정보.csv`에서 GPS와 적치장 면적을 보충합니다. `raw-data/virtual_road_edges.csv`의 소요시간 기준 최단 경로를 표시합니다. 연결 경로가 없으면 이동 목록에 표시하고 지도에는 가상의 경로를 그리지 않습니다. 비용은 원본 단위를 그대로 표시합니다.

재고는 입고일 포함·출고일 제외인 **선택 날짜 마감 재고**입니다. 점유면적은 블럭 길이×폭의 합이고, 여유 간격 반영 면적은 `scenarios/milp.json`의 `spacing_factor`를 곱합니다. 전체 적치장 면적에는 원본 면적이 알려진 적치장 모두가 포함됩니다.

이 지도는 네이버 지도처럼 탐색할 수 있는 외부 배경지도 없는 도식 지도입니다. 형상 좌표가 없으므로 시설은 GPS를 기준으로 원본 면적과 동일한 직사각형으로 환산하고 아래의 간격 보정을 적용합니다. 원본의 여러 폭/깊이는 최대 폭/깊이 비율로 종횡비를 정합니다. 원본 면적이 없는 시설은 위치 표식으로만 표시합니다.

### 시설 좌표의 겹침 보정

`scenarios/dashboard_layout.json`의 `minimum_gap_m`(기본 24m)에 따라 **모든 시설의 경계 사이에 최소 간격**을 확보합니다. 적치장부터 큰 면적순으로 놓고, 충돌하는 시설은 원래 위치에 가까운 유효 경계 후보로 옮깁니다. 결정적 알고리즘이므로 같은 데이터에서는 항상 같은 위치가 생성되며 날짜나 슬롯을 바꿔도 시설 위치가 유지됩니다.

- 보정 전 시설 겹침 25쌍(적치장 간 2쌍) → 보정 후 0쌍. 현재 입력에서 34개 시설 좌표 보정.
- `dashboard/assets/data.json`의 각 시설에 원본 GPS·`original_x/y`와 보정된 미터 좌표 `x/y`·이동량 `offset_x/y`를 함께 저장합니다. 화면은 저장된 `x/y`를 사용합니다.
- `dashboard/assets/layout.json`에서 원본/보정 좌표, 시설 면적과 치수, 겹침 검증 결과를 확인하거나 화면 하단 링크로 다운로드할 수 있습니다.
- 원본 CSV GPS, `runs/milp/result.json`의 배정·비용·이벤트, 도로의 거리·소요시간은 보존합니다. 도로 연결의 표시 끝점은 보정된 시설 위치를 사용합니다. 표시 좌표는 실제 측량 위치가 아닙니다.
- 면적이 알려진 적치장 20개, 총 126,432 m²입니다. 면적 미상인 `e4-s-no-1`은 별도 위치 표식으로 표시하며 면적 집계에서 제외합니다.

MILP 결과에는 야드 내부 배치 좌표가 없습니다. 매 날짜의 블럭을 큰 면적부터 회전 가능한 직사각형 분할 방식으로 시각화하며, 날짜가 바뀌면 내부 도형 위치가 바뀔 수 있습니다. 이는 실제 재취급 이벤트가 아닙니다. 배치되지 않는 블럭도 재고·점유면적에 포함하며 적치장 상세에 미표시 개수를 표시합니다. 내부 배치는 통로·간격·적층·물리적 배치 가능성을 검증하지 않습니다. 다른 최적화 실행인 `runs/cp-sat`의 배치 좌표는 혼용하지 않습니다.

경로 애니메이션은 보정된 지도상의 거리 / 공통 속도로 계산합니다. 모든 트랜스포터는 1× 재생에서 동일하게 지도 200m/재생 초로 움직이고, 0.5×–4×는 전체 차량에 같은 배율로 적용합니다. 긴 경로가 끝날 때까지 날짜를 유지하며, 도착한 차량은 목적지에서 정지합니다. 선택·일시정지·배속 변경으로 이동 위치가 바뀌지 않습니다. 이 속도는 시각화용 시간 압축이며 실제 운행 속도나 출발 순서를 의미하지 않습니다.

## MILP · 메타휴리스틱 · RL 비교 슬롯

지도 상단의 알고리즘 선택기로 결과를 전환하거나, 하단 **알고리즘 성능 비교**를 펼친 뒤 각 슬롯에서 **JSON 등록/교체**로 결과를 불러오고 **지도 보기**로 선택합니다. 날짜와 지도 위치·배율은 유지되며 타임라인은 등록된 결과 기간의 합집합입니다. 선택 날짜가 결과 범위를 벗어나면 지표를 `—`/`기간 밖`으로 표시합니다. 등록되지 않은 슬롯은 빈 상태로 둡니다. 슬롯 이름도 수정할 수 있습니다. 업로드 파일과 이름 변경은 현재 페이지 세션에만 적용되며 서버 파일을 변경하지 않습니다.

반복 사용할 결과는 기본적으로 다음 위치에 저장하고 데이터 생성 명령을 다시 실행하세요.

| 슬롯 | 결과 경로 |
| --- | --- |
| MILP | `runs/milp/result.json` |
| 메타휴리스틱 최선 | `runs/meta-heuristics/result.json` |
| Greedy | `runs/meta-heuristics/greedy/result.json` |
| Greedy + SA | `runs/meta-heuristics/sa/result.json` |
| Greedy + Tabu | `runs/meta-heuristics/tabu/result.json` |
| RL | `runs/rl/result.json` |
| 휴리스틱 | `runs/heuristic/result.json` |

`dashboard/slots.json`에서 슬롯 이름·경로를 설정하거나 슬롯을 추가할 수 있습니다. 파일이 없는 슬롯은 미등록으로 표시하며, 최소 하나의 결과 파일이 필요합니다.

각 알고리즘은 아래의 공통 결과 형식을 출력해야 합니다. 블럭 코드·시설 코드는 원본 CSV와 동일해야 하고 입출고일도 공통 블럭 스케줄을 따릅니다. 입출고 이동의 적치장은 `assignment`와 일치해야 합니다. 출발/도착 시설의 예시는 실제 노드 코드로 바꾸세요.

```json
{
  "total_cost": 12345.6,
  "assignment": {"B000004": "1dock-s-no-3"},
  "daily_moves": {
    "2026-01-01": [
      {"block": "B000004", "from": "1dock-P-no-1", "to": "1dock-s-no-3", "action": "입고"}
    ],
    "2026-01-02": [
      {"block": "B000004", "from": "1dock-s-no-3", "to": "1dock-f-no-1", "action": "출고"}
    ]
  }
}
```

비교표의 비용은 **실행 전체 비용**, 나머지 재고·점유·이동 지표는 **선택 날짜 기준**입니다. `배정 블럭` 열로 비교 대상 규모를 확인하세요. 동일한 대상 블럭·기간·비용식으로 실행한 결과끼리 비교해야 합니다. 현재는 공통 원본 스케줄에 대한 정적 야드 배정 결과를 지원하며, RL의 중간 야드 재배정·재취급 등 별도 이벤트 형식은 지원하지 않습니다. 간격 계수는 공통 `scenarios/milp.json` 값을 사용합니다.

로직 회귀 검증 (프로젝트 루트에서):

```sh
node dashboard/test_dashboard.cjs
python3 dashboard/test_layout.py
```

날짜별 집계·블록 경계와 겹침·미배치 재고 보존·경로 애니메이션·지도 표현 전환·줌 중심 유지·검색·재생/당일 반복·슬롯 전환·원본 격리·잘못된 JSON 거부·기간 밖 표시를 검사합니다. Python 검사는 시설 간격·등면적·GPS 보존·배치 재현성·좌표 보고서·MILP 원본 보존을 확인합니다. JavaScript 검사는 DOM/Canvas 스텁을 사용하며 실제 브라우저 렌더링 검사는 포함하지 않습니다.

## 메타휴리스틱 성능 비교

먼저 프로젝트 루트에서 `python3 run_meta.py --time-limit 5`를 실행하고 대시보드 서버를 시작하거나 데이터를 갱신하세요. `all` 모드는 그리디를 한 번 구축하고 SA와 Tabu를 각각 탐색합니다. 각 `result.json` 옆 `metrics.json`의 입력/설정 지문, 결과 SHA-256과 비용이 일치하는 실행 정보만 불러옵니다.

- 지도 상단에서 MILP / 최선 / Greedy / SA / Tabu를 즉시 선택합니다.
- 비교표는 전체 비용, MILP 저장 결과 대비 비용차, 풀이 시간, 그리디 초기해 대비 개선율, 반복 수를 표시합니다. 날짜별 재고·공간 지표도 같은 날짜로 비교합니다.
- 수렴 그래프는 탐색 시간에 따른 최선 비용과 MILP 저장 결과의 비용을 표시합니다. 중복된 최선 슬롯은 그래프에서 제외합니다.
- 기존 MILP 결과의 시간 기록이 없으면 `—`로 표시합니다. 앞으로 `main.py`로 실행한 MILP는 측정 시간을 함께 저장합니다. 단순히 시간 제한을 실행 시간으로 표시하지 않습니다.
- `metrics.json`이 없거나 결과/환경이 달라진 슬롯은 시간과 비용차를 확인 불가로 표시합니다. 업로드로 결과를 바꾸면 이전 실행 정보는 해제합니다.
- 풀이 시간은 그리디+탐색, MILP는 모델 구성+Solve입니다. 전처리와 JSON 저장은 제외합니다. 방법별 `total_seconds`는 전처리·독립 검증을 추가하며 저장은 제외합니다. 실제 일괄 실행 시간은 `runs/meta-heuristics/comparison.json`의 `elapsed_seconds`에 있습니다.

메타휴리스틱 구현과 옵션은 [상세 안내](../src/ssi_yard/planners/meta-heuristics/README.md)를 참고하세요.

## 웹에서 알고리즘 실행

실행 API가 추가되었으므로 기존 서버를 `Ctrl+C`로 종료한 뒤 `python3 dashboard/serve.py`로 다시 시작하세요. 일반 `python -m http.server`에서는 계산 버튼을 사용할 수 없습니다.

화면 상단 **알고리즘 실행**에서 다음 버튼을 누릅니다.

- **둘 다 동시 실행**: 공통 입력 스냅샷으로 MILP와 메타휴리스틱을 별도 프로세스에서 동시에 계산합니다.
- **MILP 실행**: 기본 300초 Solve 제한. 모델 구성 시간은 별도입니다.
- **메타휴리스틱 실행**: 그리디 초기해 + SA와 Tabu를 각각 설정한 시간만큼 탐색합니다.
- **실행 중지**: 현재 실행 중인 자식 프로세스를 종료합니다. 이미 완료·반영된 결과는 유지합니다.

화면 하단 **재생**은 계산을 실행하지 않고 저장된 결과의 이동 애니메이션만 보여줍니다. 동시에 실행하면 CPU·메모리를 공유하므로 시간 비교는 자원 경쟁의 영향을 받습니다. 속도를 엄밀하게 비교할 때는 개별 실행 버튼을 사용하세요.

실행 경과·종료 상태와 로그를 표시하고, 먼저 끝난 결과부터 날짜·지도 위치를 유지하며 자동 갱신합니다. 같은 서버에서 중복 계산 시작을 막습니다. 페이지를 새로고침해도 서버에서 실행 중인 작업을 다시 확인합니다. 서버 종료 시 활성 작업도 중지합니다.

모든 실행은 `runs/dashboard-jobs/<실행 ID>/`에 입력·로그·결과·작업 상태를 남깁니다. 검증을 통과하면 **MILP는 `runs/milp/result.json`**, 메타휴리스틱은 `runs/meta-heuristics/result.json`과 방법별 폴더를 덮어씁니다. 이전 결과는 실행 폴더의 `previous/`에 백업합니다. 실패·가능해 없음·반영 전 중지의 경우 이전 결과를 유지합니다. 원본 입력이 계산 중 변경되면 결과 자동 반영을 거부합니다.

API는 loopback 서버의 동일 출처 JSON 요청만 받으며, 임의 명령이나 파일 경로를 실행 인자로 받지 않습니다.

추가 검증: `node dashboard/test_runner.cjs`, `python3 -m unittest discover -s tests -p 'test_dashboard_jobs.py' -v`.

터미널에서도 통합 실행할 수 있습니다: `python3 run_planners.py --algorithm all`. MILP만 실행하려면 `--algorithm milp`, 메타휴리스틱만 실행하려면 `--algorithm meta`를 사용합니다. `--milp-time-limit 300 --meta-time-limit 5`로 각각의 제한을 지정합니다. 이 통합 실행기도 검증 후 같은 정식 `result.json`을 덮어쓰고 대시보드 데이터를 갱신합니다.
