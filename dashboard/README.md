# SSI Digital Yard 대시보드

프로젝트 루트에서 실행합니다. 별도 패키지나 지도 API 키가 필요하지 않습니다.

```sh
python3 dashboard/build_data.py
python3 -m http.server 8080 --bind 127.0.0.1 --directory dashboard
```

브라우저에서 http://127.0.0.1:8080 을 엽니다. 결과 JSON이나 CSV가 변경되면 데이터 생성 명령을 다시 실행하고 새로고침하세요. `index.html`을 파일로 직접 열면 데이터 요청이 차단될 수 있습니다.

- 날짜 선택, 일별 슬라이더, 이전/다음 날짜, 0.5–4배속 재생
- GPS 좌표를 미터로 투영한 지도에서 휠 확대, 드래그 이동, 전체 보기
- 실제 면적 비율의 적치장 및 길이×폭 비율의 블럭 도형
- 당일 입고·출고·직행 경로 애니메이션과 블럭 검색
- 적치장별 점유면적·점유율, 개별 블럭의 치수·입출고일 조회

## 데이터와 해석

`runs/milp/result.json`의 배정과 일별 이동을 사용하며, `raw-data/block_schedule.csv`에서 블럭 치수를, `raw-data/적치장 노드 정보.csv`에서 GPS와 적치장 면적을 보충합니다. `raw-data/virtual_road_edges.csv`의 소요시간 기준 최단 경로를 표시합니다. 연결 경로가 없으면 이동 목록에 표시하고 지도에는 가상의 경로를 그리지 않습니다. 비용은 원본 단위를 그대로 표시합니다.

재고는 입고일 포함·출고일 제외인 **선택 날짜 마감 재고**입니다. 점유면적은 블럭 길이×폭의 합이고, 여유 간격 반영 면적은 `scenarios/milp.json`의 `spacing_factor`를 곱합니다. 전체 적치장 면적에는 원본 면적이 알려진 적치장 모두가 포함됩니다.

이 지도는 외부 배경지도 없는 도식 지도입니다. 형상 좌표가 없으므로 시설은 GPS를 중심으로 원본 면적과 동일한 직사각형으로 환산합니다. 원본의 여러 폭/깊이는 최대 폭/깊이 비율로 종횡비를 정합니다. 원본 면적이 없는 시설은 위치 표식으로만 표시합니다.

MILP 결과에는 야드 내부 배치 좌표가 없습니다. 매 날짜의 블럭을 큰 면적부터 회전 가능한 직사각형 분할 방식으로 시각화하며, 날짜가 바뀌면 내부 도형 위치가 바뀔 수 있습니다. 이는 실제 재취급 이벤트가 아닙니다. 배치되지 않는 블럭도 재고·점유면적에 포함하며 적치장 상세에 미표시 개수를 표시합니다. 내부 배치는 통로·간격·적층·물리적 배치 가능성을 검증하지 않습니다. 다른 최적화 실행인 `runs/cp-sat`의 배치 좌표는 혼용하지 않습니다.

경로 애니메이션은 하루의 이동을 반복하는 연출이며 실제 출발 시각, 이동 순서, 차량 운행 시간을 의미하지 않습니다.

## MILP · RL · 휴리스틱 비교 슬롯

상단의 세 슬롯에서 **JSON 등록/교체**로 결과를 불러오고 **지도 보기**로 선택합니다. 날짜와 지도 위치·배율은 유지되며 타임라인은 등록된 결과 기간의 합집합입니다. 선택 날짜가 결과 범위를 벗어나면 지표를 `—`/`기간 밖`으로 표시합니다. 등록되지 않은 슬롯은 빈 상태로 둡니다. 슬롯 이름도 수정할 수 있습니다. 업로드 파일과 이름 변경은 현재 페이지 세션에만 적용되며 서버 파일을 변경하지 않습니다.

반복 사용할 결과는 기본적으로 다음 위치에 저장하고 데이터 생성 명령을 다시 실행하세요.

| 슬롯 | 결과 경로 |
| --- | --- |
| MILP | `runs/milp/result.json` |
| RL | `runs/rl/result.json` |
| 휴리스틱 | `runs/heuristic/result.json` |

`dashboard/slots.json`에서 슬롯 이름·경로를 설정하거나 슬롯을 추가할 수 있습니다. 파일이 없는 슬롯은 미등록으로 표시하며, 최소 하나의 결과 파일이 필요합니다.

각 알고리즘은 아래의 공통 결과 형식을 출력해야 합니다. 블럭 코드·시설 코드는 원본 CSV와 동일해야 하고 입출고일도 공통 블럭 스케줄을 따릅니다. 입출고 이동의 적치장은 `assignment`와 일치해야 합니다. 출발/도착 시설의 예시는 실제 노드 코드로 바꾸세요.

```json
{
  "total_cost": 12345.6,
  "assignment": {"B000004": "1dock-s-no-3"},
  "daily_moves": {
    "2026-01-01": [
      {"block": "B000004", "from": "1dock-P-no-1", "to": "1dock-s-no-3", "action": "입고"}
    ],
    "2026-01-02": [
      {"block": "B000004", "from": "1dock-s-no-3", "to": "1dock-f-no-1", "action": "출고"}
    ]
  }
}
```

비교표의 비용은 **실행 전체 비용**, 나머지 재고·점유·이동 지표는 **선택 날짜 기준**입니다. `배정 블럭` 열로 비교 대상 규모를 확인하세요. 동일한 대상 블럭·기간·비용식으로 실행한 결과끼리 비교해야 합니다. 현재는 공통 원본 스케줄에 대한 정적 야드 배정 결과를 지원하며, RL의 중간 야드 재배정·재취급 등 별도 이벤트 형식은 지원하지 않습니다. 간격 계수는 공통 `scenarios/milp.json` 값을 사용합니다.

로직 회귀 검증 (프로젝트 루트에서):

```sh
node dashboard/test_dashboard.cjs
```

날짜별 집계·도형 경계·경로 및 슬롯 전환·원본 격리·잘못된 JSON 거부·기간 밖 표시를 검사합니다. 실제 브라우저 렌더링 검사는 포함하지 않습니다.
